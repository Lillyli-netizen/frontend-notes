# 浮动布局（float）

> 原文：[CSDN](https://blog.csdn.net/qq_63283852/article/details/164632719)

**摘要**：浮动（float）是CSS中实现元素水平排列的布局方式，最初用于文字环绕；核心特性为半脱离文档流，行内文字环绕而块级背景被遮盖，并使元素块化。主要问题是父元素高度塌陷。清除浮动可用clearfix伪元素法、overflow触发BFC、额外空标签或固定高度。如今布局优先使用Flex或Grid，浮动多用于文字环绕及兼容旧项目。

---

## 一、浮动是什么？

**浮动（float）** 是 CSS 中一种用于控制元素水平排列的布局方式。它最早的设计目的是实现**文字环绕图片**的效果，后来被广泛用于多列布局。

### 1.1 float 属性值

| 属性值 | 作用 | 示例 |
| --- | --- | --- |
| `left` | 左侧浮动 | `float: left;` |
| `right` | 右侧浮动 | `float: right;` |
| `none`（默认） | 不浮动 | `float: none;` |

```css
/* 让图片左浮动，文字环绕在右侧 */
img {
    float: left;
    margin-right: 20px;
}
```

## 二、浮动的核心特性

### 2.1 文字环绕效果

浮动最初的**设计目的**就是实现文字环绕。给图片或盒子添加 `float: left` 或 `float: right` 后，后续的文本内容会自动环绕在浮动元素的周围。

```html
<!-- 图片左浮动 → 文字环绕在图片右侧 -->
<img src="photo.jpg" style="float: left; margin-right: 20px;">
<p>刘德华（Andy Lau），1961年9月27日出生于中国香港...
   这是一段很长的文字，会自动环绕在图片的右侧。</p>
```

### 2.2 脱离文档流（最核心的特性）

**浮动元素会脱离文档流（标准流）**，但浮动是**半脱离**，和 `position: absolute/fixed` 的完全脱离有本质区别。准确地说：

- 对**块级盒子**，浮动元素不再占据块级位置，后面的块级盒子会**顶上去**，其背景和边框会钻到浮动元素下面，被浮动盖住。
- 对**行内内容（文字）**，浮动元素是**占位置的**，文字所在的行框会缩短，主动绕开浮动元素，不会钻到它下面。
- 真正完全脱离、连文字都不绕、直接重叠的是 `position: absolute/fixed`。

**直观理解**：

```css
【正常文档流】
┌─────────────────────────┐
│ 盒子1（标准流，占位置）   │
│ 盒子2（标准流，占位置）   │
│ 盒子3（标准流，占位置）   │
└─────────────────────────┘
【盒子2左浮动后】
┌─────────────────────────┐
│ 盒子1（标准流，占位置）   │
│ 盒子2（浮动，不占块级位置）│← 浮在左上角
│ 盒子3（标准流，顶上来）   │← 背景/边框占用了盒子2的位置
└─────────────────────────┘
```

注意，上图“盒子3占用了盒子2原来的位置”只对盒子3的**背景和边框**成立，盒子3里面的**文字是绕开盒子2的**。绘制顺序也能佐证这一点，浮动盖在块级背景之上，行内文字之下。

### 2.3 浮动对 display 的影响（块化 blockify）

先看一个反直觉的现象：`<a>`、`<span>` 这种行内元素，本来设 `width/height` 是没用的，上下 `margin/padding` 也不生效。但一旦加上 `float: left/right`，它就被块化了：

- 可以直接设 `width`、`height`
- 上下 `margin`、`padding` 全部生效
- 不用再写 `display: block` 或 `display: inline-block`

这就是**块化（blockify）**，元素一旦浮动，会被自动转成块级盒参与布局。多个浮动元素横向并排，一行放不下就换行，表现很像行内块。但注意，规范上它**不是变成 inline-block**。

> 两个规则：
>
> - 浮动元素的 `margin` 不会发生外边距塌陷。
> - 浮动元素 `margin: 0 auto` 无效（`auto` 会被算成 0），所以浮动不能直接居中。

**排列规则**：浮动元素尽量往左上或右上靠，但顶边不能高过它前面的浮动元素或块级元素，一行放不下就掉到下一行。这解释了为什么多个浮动盒子有时会卡在半空而不是贴顶。

## 三、浮动带来的核心问题

### 3.1 父盒子高度塌陷

**现象**：当父盒子中的所有子元素都浮动时，父盒子无法感知到子元素的高度，导致父盒子的高度**塌陷为 0**（或只剩 padding 和 border）。

**为什么会塌陷？**

- 浮动元素脱离文档流，不占据空间
- 父盒子默认靠子元素撑开高度
- 子元素都浮动了，父盒子就“以为”自己里面没有内容，高度归零

**后果**：

- 父盒子的背景色、边框无法正常显示
- 父盒子后面的元素会顶上来，造成布局错乱

```html
<!-- 例子：父盒子高度塌陷 -->
<div class="father">   <!-- 背景色几乎看不到，高度≈0 -->
    <div class="son" style="float: left; width:100px; height:100px;">浮动</div>
    <div class="son" style="float: left; width:100px; height:100px;">浮动</div>
</div>
<!-- 后续元素会顶上来，紧贴浮动子元素 -->
<p>我是后面的文字，我顶上来了！</p>
```

### 3.2 影响后续元素布局

浮动元素不占位置，会导致后面的标准流元素**位置错乱**，跑到了浮动元素的下方甚至重叠。

## 四、清除浮动（闭合浮动）

清除浮动的本质是**闭合浮动**，即让父盒子**感知内部浮动子元素的高度**，不让浮动影响外部布局。

### 4.1 方案一：clearfix 伪元素法

使用 `::after` 伪元素 + `clear: both`，在父盒子内部末尾生成一个看不见的块级元素，清除浮动。

```css
/* 定义一个通用类 clearfix */
.clearfix::after {
    content: "";          /* 必须有内容（空字符串也行） */
    display: block;       /* 转为块级元素 */
    clear: both;          /* 清除左右浮动 */
}
```
```css
<!-- 父盒子添加 clearfix 类 -->
<div class="father clearfix">
    <div class="son" style="float: left;">浮动元素</div>
    <div class="son" style="float: left;">浮动元素</div>
</div>
<!-- 父盒子高度被撑开，后面的元素不影响 -->
<p>footer</p>
```

**优点**：无额外标签、语义干净、兼容性好。

### 4.2 方案二：父盒子 overflow: hidden（触发 BFC）

**BFC（Block Formatting Context，块级格式化上下文）**是 CSS 渲染时的一块**独立布局区域**。可以把它理解成一个**封闭的小世界**：

- 区域内部的元素，**不会影响**区域外部的布局；
- 区域外部的元素，也**进不来**干扰内部。

所以当父盒子触发 BFC 后，它就能把内部的浮动子元素**“圈”在自己里面**，从而感知到它们的高度，解决高度塌陷。

**常见触发方式**：

- `overflow: hidden` / `auto` / `scroll`
- `display: flow-root`
- `display: inline-block` / `table-cell` / `flex` / `grid`
- `position: absolute` / `fixed`
- `float`

给父盒子设置 `overflow: hidden`，触发 **BFC（块级格式化上下文）**，让父盒子包裹住浮动子元素。

```css
.father {
    overflow: hidden;   /* 或 auto */
}
```

**优点**：代码简洁，一行搞定。
 **缺点**：如果子元素有超出父盒子的内容（如下拉菜单、阴影），**会被裁剪掉，不推荐使用**。

### 4.3 方案三：额外空标签法

在父盒子内部最后添加一个空的块级标签，设置 `clear: both`。

```css
<div class="father">
    <div class="son" style="float: left;">浮动</div>
    <div class="son" style="float: left;">浮动</div>
    <div style="clear: both;"></div>  <!-- 额外的空标签 -->
</div>
```

**缺点**：增加无意义的 HTML 结构，违反结构与样式分离原则。

### 4.4 方案四：父盒子固定高度

直接给父盒子设置固定的 `height`，强行撑开。

```css
.father {
    height: 200px;   /* 手动固定高度 */
}
```

**缺点**：高度无法自适应子元素内容，维护困难，不灵活。

## 五、浮动的使用场景

### 5.1 仍适合使用浮动的场景

| 场景 | 说明 |
| --- | --- |
| **文字环绕图片** | 这是浮动最初的设计目的，至今仍然是实现文字环绕的最佳方式 |
| **兼容旧浏览器** | 需要兼容 IE8 及以下版本时，浮动是主要布局手段 |
| **特定水平排列** | 在没有 Flex 或 Grid 的历史项目中 |

### 5.2 已被替代的场景（请用 Flex/Grid）

| 旧方案（浮动） | 现代方案（推荐） |
| --- | --- |
| `float: left` 做导航栏 | **Flexbox**（`display: flex`） |
| `float: left` 做多列布局 | **Grid** 或 **Flexbox** |
| 清除浮动用 `clearfix` | Flex/Grid 天然无此问题 |
| 浮动实现水平居中 | Flex 的 `justify-content: center` |

> **总结**：现在**布局请优先使用 Flexbox 或 Grid**。浮动只在**文字环绕**和**兼容旧项目**时使用。
